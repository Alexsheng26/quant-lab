**English** | [简体中文](README.zh-CN.md)

A no-build, zero-dependency browser workbench for US equities: charting, backtesting,
paper trading, and a set of research agents that rank a stock against the whole market,
scan its news, and read its SEC filings.

## What's interesting here

The features are ordinary; most of the work went into making them correct and honest.

- **Charts drawn by hand on Canvas** — candlesticks, equity curves and a hexagon radar,
  with no charting library and no build step. The frontend is plain `<script>` files;
  double-clicking `index.html` works.
- **A backtester that cannot see the future.** A signal formed on bar *i*'s close fills at
  bar *i+1*'s open, with fees and slippage. This is pinned by tests, including one that
  feeds a series that only spikes on its last bar.
- **SEC financials from XBRL, not PDFs** — and a fix for a subtle trap: `fp == "FY"` describes
  the *filing*, not the data point, so a 10-K's quarterly comparatives get mislabelled as
  annual figures. NVIDIA's FY2020 revenue showed up as $3.0B (one quarter) instead of $10.9B.
- **Year-over-year diff of 10-K risk factors.** The comparison is computed locally and
  deterministically; an LLM only interprets the changed paragraphs. The first algorithm failed
  on real filings, and the fix — plus the cases where it still shouldn't be trusted — is
  [written up below](#10-k-risk-factor-changes).
- **A strict rule for LLMs: numbers come from code, words come from the model.** Scores,
  percentiles and backtest results are reproducible pure functions. Models only read text,
  and every prompt forbids them from producing new numbers or giving advice.
- **WCAG 2.1 AA, verified by scripts** rather than by sprinkling ARIA attributes: axe-core
  reports 0 violations (baseline: 195), and a keyboard-only walkthrough passes 24/24 checks.
- **195 tests, about 5 seconds, no network**, run in CI on Python 3.11–3.13 and Windows.
  The frontend's 56 assertions run in a real Chromium against the actual source files.

## Quick start

### Just looking → open the live demo

<https://alexsheng26.github.io/quant-lab/> — nothing to install.

It runs the built-in market simulator, and **the chart carries a "simulated data" watermark**.
Simulated prices are synthetic and unrelated to real quotes; only the trading calendar is real.

### Real quotes → run the backend

Install once:

```bash
python -m venv .venv
.venv\Scripts\pip install -r backend/requirements.txt      # Windows
.venv/bin/pip install -r backend/requirements.txt          # macOS / Linux
```

Then, on **Windows, double-click `quantlab.bat`**. It starts the backend, waits until it is
ready, and opens the page. The badge in the top-right turns green (`LIVE`) when connected.

Elsewhere, or to watch the backend log:

```bash
.venv/bin/python backend/app.py          # serves on 127.0.0.1:8000 (Windows: .venv\Scripts\python)
```

…then open `index.html`. On load the page probes `127.0.0.1:8000` and switches to live data
if the backend answers.

The [live demo](https://alexsheng26.github.io/quant-lab/) can use your local backend too, but
recent Chrome and Edge first ask for permission before a public website may reach your local
network. Allow it (and reload if the page is still on simulated data); otherwise the request is
blocked. Opening the local `index.html` — which is what `quantlab.bat` does — needs no permission.
Safari blocks HTTPS pages from calling a local HTTP backend altogether.

> After pulling changes, hard-refresh with **Ctrl+F5**. Static servers here send no
> `Cache-Control`, so browsers happily keep running yesterday's JavaScript.

### Optional: LLM features

News Q&A, the risk-factor interpretation and the Panorama brief use an LLM when one is configured,
and fall back to retrieval / plain diffs when not.

```bash
cp .env.example .env          # then set DEEPSEEK_API_KEY or ANTHROPIC_API_KEY
```

See [Where LLMs are used](#where-llms-are-used-and-where-they-deliberately-arent) for details.

| File | When to use it |
| --- | --- |
| `quantlab.bat` | **Day to day** (Windows): start backend + open page |
| `index.html` | Page only; without a backend it shows simulated data |
| `run-backend.bat` | Backend only, keeping the window open to read errors |
| `serve.bat` | Rarely needed: serves the frontend over HTTP at `localhost:5500` |

> The `.bat` files are deliberately ASCII-only. `cmd.exe` reads batch files by byte offset in
> the active code page, so UTF-8 Chinese text (especially combined with `chcp`) desynchronises
> the parser in baffling ways.

- Filtering out names containing `depositary shares` as "noise" silently removed **every ADR**

## Design notes

**One data interface.** Everything above the data layer calls `search` / `getHistory` /
`getQuote`, so swapping simulated data for a live feed touches no business logic.

**Simulated data is a factor model, not noise.** Each stock follows
`return = drift + beta × market shock + idiosyncratic shock`. The market factor has volatility
clustering and occasional sell-offs; stocks add their own clustering and earnings gaps. So
watchlist names move together, betas and correlations are real, and a symbol always gets the
same seed — refreshing does not change its history.

**Weekly and monthly bars are resampled from daily bars**, and the annualisation factor follows
the interval (252 / 52 / 12). Forgetting that inflates weekly annualised volatility by about √5,
which is the classic mistake when adding an interval selector. The app loads 1,800 daily bars
(~7 years), which resample to ~87 monthly bars — just enough for a monthly MA60; three years
gave only 37. When a sample is too short, backtests and scores refuse to run and say how many
bars are missing.

**Fibonacci retracement: direction can't be guessed.** Levels are drawn between the visible
range's high and low, and **which end is 0% depends on which extreme came last**:

| Swing | Rule | 0% | 100% | Levels mean |
| --- | --- | --- | --- | --- |
| Up | low came first | high | low | pullback support |
| Down | high came first | low | high | bounce resistance |

Get it backwards and 38.2% and 61.8% swap places — the lines still look plausible and the
numbers still add up, but the reading is inverted. A test feeds the same prices in both orders
and requires different levels. (These levels are arithmetic on past extremes, not predictions.)

**Async results must be claimed.** A live fetch takes 0.5–2 s and quotes poll every 2 s. Click
two symbols quickly and the first response can land after the second, writing the old stock's
price under the new ticker. Requests carry a sequence number and are dropped if stale.

**Automatic decisions are not user preferences.** The data mode is persisted only when the user
clicks the badge — never when the app falls back on its own. An early version stored the
automatic fallback to `"mock"`, after which the app treated it as the user's choice and stayed
on fake prices even with the backend running.

**Scores are not a black box.** Five factors each score 0–100 and are weighted
(edit `agentWeights` in `config.js`); every conclusion lists the values that produced it.

| Factor | Weight | Looks at |
| --- | --- | --- |
| Trend | 30% | Price vs. MA20/MA60, MA alignment, MA20 slope |
| Momentum | 22% | RSI(14), ROC20/60, MACD histogram |
| Risk | 16% | ATR%, annualised volatility, 60-day max drawdown (lower is better) |
| Volume | 14% | 5/20-day volume ratio, OBV slope — must agree with price direction |
| Position | 18% | Bollinger %B, 52-week range percentile (overheating is penalised) |

**Reference levels describe, they don't predict.** The score panel offers a probe-entry level, a
deeper entry level and an invalidation level, each with its source and distance from price. The
directional read is phrased as "current structure, and what would change it" (e.g. *a close below
319.89 weakens the structure*) rather than "it will go up" — technical indicators are functions of
past prices, and only falsifiable conditions can be checked. When the price sits at a 60-bar low,
or fewer than two support levels exist below it, the "support" would just be volatility
extrapolation, so the panel shows a warning instead of inviting a falling-knife entry.

## The three agents

The Panorama tab puts all three side by side: when you look up a stock, you want the whole
picture without switching pages.

### ① Quant agent · market-wide percentiles

Answers questions like "where does its P/E rank in the market, and how many peers does its ROE
beat?" by **cross-sectional ranking**: `build_universe_snapshot.py` stores fundamentals for the
503 S&P 500 constituents (~27 s to build), and each metric of the target stock is ranked against
that pool and against its sector.

Six axes form the radar: valuation (P/E, P/B, EV/EBITDA — inverted), profitability, growth,
quality, momentum and size. The verdict labels the shape — *hidden gem*, *value trap*,
*growth premium*, *valuation unsupported* and so on. Three things that are easy to get wrong:

- **A 2×2 grid is not enough.** "Cheap/expensive × strong/weak" leaves the cases where one side
  is extreme and the other is middling to a catch-all that said "no significant deviation" — for
  a stock at the 9th valuation percentile. It is now a 3×3 grid.
- **Don't average profitability and growth.** NIO sat at the 1st profitability percentile and the
  99th growth percentile; averaging gives a bland 50. A gap of 40+ percentiles now gets its own
  verdict (*growth not yet profitable* / *profitable but not growing*).
- **No total score without enough data.** An ETF with 2 of 6 axes used to get a total of 76, which
  reads like a complete rating. At least four axes are now required.

### ② News agent

Pulls Yahoo Finance news, scores each article with a finance-specific sentiment lexicon, and shows
**where the news comes from**: a single dominant source is its own echo chamber, so the source
distribution is displayed, and any outlet supplying 60% or more of the articles is flagged.

Q&A has two levels, and **the UI always says which one you're looking at**:

| Mode | When | Output |
| --- | --- | --- |
| Retrieval (default) | No LLM key | TF-IDF-ranked excerpts with sources, labelled "retrieval, not generative" |
| Generative RAG | DeepSeek or Claude configured | A synthesis across articles with `[n]` citations, confidence and caveats, labelled with the model name |

Without an LLM, it never writes a fluent paragraph that would pass for an AI summary. The model
only sees the top-ranked excerpts, which keeps citations traceable; articles are wrapped in
`<articles>` tags and declared as data, because a headline can contain "ignore previous
instructions".

### ③ Research agent · filings and financials

Uses the official **SEC EDGAR** APIs (free, no key) and **reads XBRL instead of parsing PDFs**:
companies must file machine-readable financials, so revenue, net income, equity and cash flow come
back as structured data. Concepts that changed tags over the years
(`Revenues` vs. `RevenueFromContractWithCustomerExcludingAssessedTax`) are tried in priority order,
and restatements are de-duplicated.

The annual filter checks **the length of each data point's period** (300–400 days), not the
filing's `fp` field — see the NVIDIA example above. ETFs and some ADRs are not registered with the
SEC; the agent says so instead of showing an empty panel.

### Panorama brief

The top of the Panorama tab weaves the three agents' conclusions into one paragraph. The most useful
part is **`conflicts`**: where the agents disagree — cheap on percentiles but negative in the news,
top-decile profitability but middling quality. You can't see those by reading any one agent.

Two deliberate choices:

- **Nothing is uploaded.** The backend reads the agents' conclusions from its own cache. Letting the
  browser POST them would let anyone put arbitrary text into the prompt.
- **Conclusions only, no raw data.** The model sees "valuation 12th percentile" and "net margin
  26.9%", never price bars. Its job is to connect and restate, not to analyse.

## Where LLMs are used (and where they deliberately aren't)

The rule is one sentence: **numbers come from code; words come from the model.**

Scores, percentiles, backtests and Fibonacci levels are reproducible pure functions. The model does
three language tasks, and the prompts forbid it from producing new numbers or giving advice — tests
pin those constraints so they can't be deleted by accident.

| Use | Does | Doesn't |
| --- | --- | --- |
| News Q&A | Answers from retrieved excerpts with `[n]` citations | Add its own knowledge |
| 10-K risk-factor changes | Interprets paragraphs the local diff flagged | Read whole filings or do the diff |
| Panorama brief | Connects computed conclusions; points out conflicts | Do arithmetic or introduce numbers |

### Providers

Both are optional; with neither configured, these features fall back to retrieval or a plain diff
instead of failing or pretending.

| Provider | Role | Why |
| --- | --- | --- |
| **DeepSeek** | Default | Directly reachable from mainland China and one to two orders of magnitude cheaper. For long inputs like 10-K text, cost decides whether the feature can be on at all |
| **Claude** | Alternative | Structured output is enforced by the model, which is more reliable |

With both configured, DeepSeek is used; set `LLM_PROVIDER=claude` to switch. Model names and base
URLs are overridable through environment variables, so a vendor rename doesn't require a code change.

The two differ in a way that matters: Anthropic's `json_schema` output is enforced model-side, while
DeepSeek's OpenAI-compatible `response_format` only guarantees valid JSON, not the required fields.
So the abstraction validates every response itself and treats a missing field as a failure, rather
than letting half an object reach the page. Errors are also scrubbed of anything that looks like an
API key before they leave the server — an SDK's authentication error can contain the key itself.

> ⚠️ **Never paste an API key into a chat, issue, screenshot or anywhere public.** Revoke any key
> that has been exposed; keys pushed to GitHub are typically harvested within minutes. `.env` is in
> `.gitignore`.

## 10-K risk-factor changes

The research agent originally did half the job: list filings, pull XBRL numbers. "No need to read
hundreds of pages yourself" was missing the half that matters — the **text**.

Companies rewrite Item 1A (Risk Factors) every year, and a newly added risk often means management has
started worrying about something, sometimes before it shows up in the numbers. Analysts do this
comparison by hand; two legal documents of several dozen pages each take hours to compare.

**The diff is computed locally; the model only interprets it.** That removes over 90% of the tokens
and keeps every conclusion traceable — each new risk is shown with a verbatim quote from the filing.
For Apple's FY2025 10-K it surfaced US tariffs and the Section 232 semiconductor investigation, the
Google antitrust remedies that threaten search-distribution revenue, and copyright risk from AI
training data.

### The first algorithm failed on real filings

Version one paired paragraphs with `difflib` fuzzy matching. It looked great on synthetic tests; on
real filings it reported **40% of Apple's risk paragraphs as "new"** — including "a majority of net
sales come from outside the US" and "manufacturing is outsourced to partners in mainland China",
which appear every year.

The cause: companies re-split paragraphs. What was two paragraphs last year becomes one this year,
and half a paragraph matches a whole one at a similarity of about 0.5 at best. **No threshold fixes
that** — dropping it from 0.75 to 0.5 only cut the false positives from 38 to 29.

The fix is **n-gram coverage**: measure how much of each paragraph's 5-grams appear anywhere in the
other year's section. Merging and splitting no longer matter.

| | Paragraph pairing | n-gram coverage |
| --- | --- | --- |
| "Manufacturing is outsourced…" paragraph | 0.15 (false "new") | **0.84** (correctly old) |
| Share of Apple's paragraphs flagged new | 40% | **9.5%** |

### When not to trust it

Handled layout differences: Microsoft's body heading is just `Item 1A` (no "Risk Factors"); 20-F
filings use `Item 3.D` instead (this covers Chinese ADRs); JPMorgan files so often that older annual
reports have to be fetched from paginated archives.

After that, across eight companies (share of the new filing's paragraphs flagged as new):

| Company | Flagged new | Verdict |
| --- | --- | --- |
| KO / NIO / AAPL / NVDA / TSLA / MSFT | 1.1% – 19.6% | Normal |
| JPM | 43.8% | Not reliable — heavy rewording |
| BABA | 97.2% | Not reliable — section mislocated |

The two failures have different causes:

- **BABA is a parsing problem.** 20-F layouts vary much more than 10-Ks, and the extracted sections
  don't line up between years.
- **JPM is a limit of the method, not a bug.** It rewrote old content, such as reputational risk, into
  lead-in sentences with bullet lists. The text is new; the risks are not. n-gram coverage measures
  whether *text* is new, not whether a *risk* is new — the heavier the rewrite, the less "new" means.

So results above **30%** are marked unreliable, the likely causes are explained, and **no model call is
made**. The threshold sits between the highest normal value (19.6%) and JPM (43.8%). It started at
60%, which only caught BABA — JPM's half-right result would have been presented as normal, with a
fluent model summary on top. A confident interpretation of unreliable input is worse than saying
"not sure".

## Built-in strategies

| Strategy | Rule |
| --- | --- |
| MA crossover | Long when the fast MA crosses above the slow MA; exit on the cross back |
| RSI mean reversion | Buy below a threshold, sell above another |
| MACD | Long when the histogram turns positive |
| Bollinger breakout | Long on a break above the upper band; exit below the middle band |
| Donchian channel | Long on an N-day high; exit on an M-day low (turtle-style) |
| Buy and hold | Benchmark |

Metrics: total return, CAGR, max drawdown, Sharpe, Calmar, annualised volatility, trade count,
win rate, profit factor, average holding period, exposure, fees, and excess return over buy-and-hold.

## Testing

**195 tests, about 5 seconds, no network.**

```bash
pip install -r requirements-dev.txt
python -m playwright install chromium
python -m pytest
```

Backend only, no browser (~1.5 s):

```bash
python -m pytest -m "not js and not a11y"
```

| File | Covers |
| --- | --- |
| `tests/test_research.py` | XBRL annual detection, restatement de-duplication, class-share CIK lookup |
| `tests/test_fundamentals.py` | Percentile ranking, all nine verdict cells, profitability/growth divergence, total-score threshold |
| `tests/test_search.py` | Ranking order, word-boundary penalties for leveraged products, aliases, response projection |
| `tests/test_llm.py` | Provider selection, key scrubbing, each provider's failure paths, prompt-injection isolation, prompt constraints |
| `tests/test_filing_text.py` | 10-K extraction, diffs across merged and split paragraphs, the reliability threshold |
| `tests/test_api.py` | Routes and response models, rate limiting, CORS, LLM endpoints' fallbacks |
| `tests/test_js.py` + `tests/js/` | Frontend: indicators, Fibonacci, backtest engine, performance stats |

**Why the frontend tests run in a browser.** The frontend is plain `<script>` files with no
`package.json` and no module system. Rather than add an npm toolchain just for tests, Playwright —
already used for the accessibility audit — loads the **real source files** into Chromium and runs the
assertions there, which is where that code actually runs. Locally and in CI, Python is the only toolchain.

Data sources are mocked throughout, `conftest.py` blocks any connection to a non-loopback address, and
real API keys are removed from the environment, so flaky upstreams can't turn CI red and a test can
never call a paid API.

Bugs these tests caught:

- `llm.py` returned upstream error messages verbatim; an SDK's auth error can include the API key,
  which would have been printed in the browser.
- The Sharpe ratio exploded on near-constant returns: `vol === 0` misses the ~1e-19 left by
  floating-point error, producing values around 2×10¹⁶.
- A caching helper set `ok: true` on every result, turning a deliberate "no API key" failure into a success.
- HTML stripping emitted single newlines while paragraph splitting expected blank lines, so whole
  sections collapsed into one paragraph and the diff silently stopped working.

```bash
.venv\Scripts\python backend\audit_a11y.py    # axe-core, every tab, plus hover states
.venv\Scripts\python backend\audit_keyboard.py
```

Current results: **axe-core 0 violations** (initial baseline: 195 instances across 2 rules) and
**keyboard walkthrough 24/24**.

| Area | What was done |
| --- | --- |
| Contrast | Faint text raised from 2.73:1 to AA. Solid buttons use dark text on the brand colours (6.0–6.4:1) instead of darkening the colours — green/red mean up/down across every chart |
| Keyboard | Tabs follow WAI-ARIA (single tab stop, arrow keys, Home/End); search results reachable with ↓, selectable with Enter, dismissed with Esc |
| Skip link | First tab stop jumps past the header and watchlist to `#main` |
| Focus | `:focus-visible` rings for keyboard users only |
| Charts | All three canvases (candles, equity curve, radar) have live `aria-label`s that state the numbers in a sentence, including Fibonacci levels when shown |
| Screen readers | tablist/tabpanel, combobox/listbox, `aria-pressed` on toggles, `role="status"` toasts, focusable scroll regions |
| Motion | Honours `prefers-reduced-motion` |

The two scripts catch different things. axe-core inspects static markup, so it can't see "Tab never
reaches this" or "the primary button turns grey on hover" — the latter even passes contrast at 10.9:1.
It is a CSS specificity regression, so `audit_a11y.py` asserts it separately.

## Deployment

The frontend is static and the backend is Python, and GitHub Pages can only host the former:

| Part | Hosted on | Result |
| --- | --- | --- |
| Frontend (`index.html` + `assets/`) | GitHub Pages, published on every push | Opens anywhere, uses the simulator |
| Backend (`backend/`) | The visitor's own machine | Clone and run it for live data |

`.github/workflows/pages.yml` publishes `index.html` and `assets/` on pushes to `main` (with
`.nojekyll`). First time only: **Settings → Pages → Source → GitHub Actions**.

`render.yaml` is a blueprint for Render's free tier if you want to host the backend. Before doing so:

1. **Free instances sleep after 15 idle minutes**; a cold start takes 30–60 s.
2. **Yahoo often throttles data-centre IPs**, so yfinance may fail intermittently.
3. **A deployed key is anyone's key.** Generative endpoints are limited per IP
   (`LLM_CALLS_PER_HOUR`, default 30; over the limit they degrade instead of erroring), but IPs change.

You **must** set `ALLOWED_ORIGINS`, or CORS stays open to every website:

```
ALLOWED_ORIGINS=https://<your-username>.github.io
```
